[ 01 / 07 ] · The blind spotwhy nothing catches it
[ ANNOUNCED 2020-01-21 ] [ BROKE 2022-03-01 ]
No version, no bump, no warning

An API identifier has
nothing to upgrade.

Dependabot watches your manifest. Renovate watches your manifest. Both are excellent, and both are looking somewhere else — a model name, an endpoint path and a request parameter live in your source code, not your dependency graph. Nothing pins them, so nothing flags them. They keep working right up until the provider turns them off.

Providers do announce it. That has never been enough. The announcement lands in a changelog months or years before the shutdown, and somebody still has to map the prose onto their own call sites.

[ 07 / 07 ] · Why it stays quietprecision first
The only number that decides whether you keep it on

A scanner that cries wolf
gets muted, then deleted.

An early build reported 86 findings on a real 1,200-dependency repository. About a quarter were true — refund was matching inside refunded. That tool is worse than nothing, because it teaches you to ignore it. Every artifact kind now matches only in the exact shape it takes when it is actually sent to a provider.

86
findings · ~25% true
→
5
findings · 100% true

Every claim carries its source

A finding links to the provider's own deprecations page or the spec diff it came from.[3] One click to check it. You are never asked to trust us, and no language model sits anywhere in the detection or fix path.

Severity is a countdown

"Deprecated, retires 2026-10-23" is not a footnote, it is a date getting closer. Findings sort by time remaining — 88 days left above, dead 935 days below. No dependency tool has a field for that.

It stops at the guess

Only replacements the provider itself named get written, using the quoting your file already uses. Anything that needs a judgment call is reported and left alone, and it says so out loud.
